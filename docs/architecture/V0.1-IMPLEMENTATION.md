# V0.1 Implementation Baseline

V0.1 completes the first usable vertical slice without entering the later Spider/Drpy/T4 scope.

## Implemented flow

`Renderer -> Preload -> Main IPC -> Source Engine UtilityProcess -> CMS Adapter -> RequestBroker`

Playback continues through:

`Detail episode -> Main playback orchestration -> PlayerClient -> Windows Named Pipe -> player-host.exe -> libmpv 0.41.0`

## Persistence

`services/data-service` owns SQLite persistence through the Node.js 24 `node:sqlite` `DatabaseSync` API. The renderer and adapters never access SQLite directly. V0.1 persists source definitions and the newest 200 playback-history rows.

The architecture v1.1 originally preferred `better-sqlite3`. During real Windows x64 CI, `better-sqlite3` 13.0.3 had no prebuilt binary for the Node 24.19 runner and its fallback MSVC build failed inside the SQLite amalgamation with C2026. ADR-009 records the decision to keep SQLite while removing the fragile external native addon.

## V0.1 source scope

- `T1_JSON`: CMS JSON home/search/detail/direct play.
- `T0_XML`: CMS XML home/search/detail/direct play.
- Direct HTTP(S) episode URLs only.
- Parser/sniffing pages intentionally return an explicit V0.3 capability error instead of silently failing.

## Player runtime

Windows CI pins official mpv v0.41.0 `x86_64-pc-windows-msvc` by URL and SHA-256. `libmpv-2.dll` is placed beside `player-host.exe` in the packaged application. Nightly downloads are prohibited.
